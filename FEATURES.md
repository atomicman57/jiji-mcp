# Feature coverage — 0.3.0

Audited on 2026-10-27 against Jiji’s live web interface, public application route/API definitions and [help centre](https://jiji.ng/faq). This is an independent integration of the web product; undocumented endpoints can change and account, category, country or subscription restrictions still apply.

The server exposes **21 tools**, including a catalog of **73 read resources**, **35 owner-approved actions**, and **42 browser workflows**. [FEATURES.json](FEATURES.json) contains exact names and parameter schemas. `jiji_capabilities` provides the same inventory to agents.

“Direct read” means an implemented, fixed browser-origin request or rendered-page reader. “Prepare” means an exact local approval plan; preparation never submits the change. “Owner workflow” opens the relevant Jiji page for manual final steps. These are distinct levels of support. A mapped endpoint is not evidence that it has been exercised successfully on every account.

## Verification boundaries

Automated tests cover schemas/routing, browser-origin restrictions, credential redaction, paid-field rejection, advert create/edit identity, OAuth isolation and expanded consent, local CSRF protections and one-time approvals. Public research and authenticated account reads have been exercised through the dedicated companion and connected clients. Of 49 read resources accepting empty parameters, 46 succeeded; orders and two advert-sharing resources returned HTTP 404 on the tested account/site. Identifier-dependent reads and real writes are not all live-tested. See VALIDATION.md for client evidence and limits.

No test sends a real seller message, publishes an advert, purchases a package, changes credentials, uploads identity documents or permanently deletes account data. Such effects cannot be called “live-tested” from fixtures alone.

Opening the 42 workflows provides an owner handoff for the remaining feature areas; it does **not** mean the MCP fully automates every Jiji feature. Native-app features and future platform changes require separate implementation and verification.
